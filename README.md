<h3 align="center">Support Engineer focused on diagnosing and improving real-world systems</h3>

I work across technical support, software and operations. My background in full-stack development helps me trace problems through the whole system: browser, API, data, automation and infrastructure.

I care about clear reproduction steps, useful logs and fixes that stop the same incident from returning.

## What I work with

- API and application troubleshooting with REST, Postman, SQL and browser developer tools
- JavaScript, TypeScript, React, Node.js, Java and Spring Boot
- Linux services, Proxmox, nginx, Cloudflare and Tailscale
- Monitoring, health checks, backup and recovery procedures
- Automation with scripts, Notion integrations and n8n

## Selected work

### [Agent Mission Control](https://github.com/leveretlogic/agent-mission-control)

Operations dashboard for a live multi-agent system. It exposes stale data, health failures and pending approvals instead of hiding them behind a green status screen. The repository includes the post-mortem of a first version that failed silently and the safeguards built into its replacement.

### [AI Reliability Patterns](https://github.com/leveretlogic/ai-reliability-patterns)

Small TypeScript patterns for approval gates, watchdogs, heartbeat freshness and stale-action fallbacks. Each pattern explains the failure it prevents, the trade-offs involved and where it fits in a production system.

### [Industrial Productivity Tracking](https://github.com/leveretlogic/industrial_productivity_tracking)

Engineering case study of a factory-floor system built for iPad 2 kiosks. It covers offline registration, API retry behavior, Notion-backed data and the move from cloud hosting to a local Proxmox deployment.

### [Proxmox Homelab Infrastructure](https://github.com/leveretlogic/proxmox_homelab_infrastructure)

Operational documentation for a self-hosted Proxmox platform. It covers service isolation, private and public network access, security hardening, health checks, backups and recovery.
